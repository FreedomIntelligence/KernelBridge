# Pi 原生工具与业务工具：功能测试和验收范围

日期：2026-11-09。实现基线：`4aa47a903ba532790852067561f8fae4c7dc27ed`；导入基线：`87c8fe4059988344c4ddd001fb38f1402e359b93`。

目标是验证完整工作链：任务与配置进入 KernelCat，Pi 使用基础工具生成候选，业务工具提供知识、NPU 评测和原始凭据，KernelBridge 执行权限与预算控制，LoopX 管理多 Trial 的目标和调度。

“已通过”只适用于记录的场景和环境。“部分通过”表示已有可复现证据，但该功能还有未覆盖场景。“待验收”不能以静态检查或模拟模型替代。推送修复提交不等于所有平台或生产部署验收完成。

## 执行顺序与放行条件

1. **提交回归**：每次触及工具/协议/正确性执行下列 22 项仓库用例、类型检查、schema/交付检查。失败不得报告该修复已通过。文档更新至少检查链接、清单摘要和命令有效性。
2. **部署环境验收**：在干净 macOS 和 Linux 环境安装固定依赖，补齐 F01/F03/F04/F08。NPU 部署前完成 F09 的编译、加载、设备和失败路径；不能用 torch_npu 样例替代 Ascend C 工具链验收。
3. **在线 Agent 验收**：固定任务、模型、版本和步数/时间/费用预算，至少覆盖简单生成、边界输入、需修复错误、需查知识和需恢复会话五类场景；记录每轮工具和候选变化。先单 Trial，再多 Trial。不得把脚本驱动的通过数合并成模型成功率。
4. **性能验收**：正确性、身份绑定和设备环境通过后，按任务契约执行同设备交错成对测量并保留原始样本。指定目标 SoC、空闲条件、计时范围和噪声处理；没有实测就标记未验收，不估算提升。

以上是功能验收定义。当前推送范围是已实现的工具迁移、五项问题修复、仓库回归和本文档；待验收项保持公开记录，不以修复推送宣称整套系统已完成验收。
