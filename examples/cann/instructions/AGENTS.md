# AGENTS.md — 通用算子优化

适用于 CPU、GPU、NPU 上的独立算子、融合算子及其调用链。优化真实执行成本，在明确的语义、精度和资源约束下改善目标工作负载。探索路线保持开放，验收条件在每轮实验前固定。

## 1. 先确定任务合同与目标

- 读实际调用入口、参考实现和已有测试，明确输入与全部输出，包括可选输出、状态更新、梯度、别名和原地修改。参考实现用于理解语义，不要求复制其中间步骤。
- 记录合法输入域：shape、dtype、stride、布局、对齐、设备、模式及动态参数。明确空输入、尾部、溢出、NaN/Inf、并列顺序、索引、舍入和确定性中与本任务相关的要求。
- 优化须对合同内的新输入成立，不能以固定样例或预存答案代替计算。专用路径未命中时保持合法输入覆盖；报错只能用于合同外输入，不能暗中缩小接口能力。
- 明确精度合同：逐位一致、容差内一致或已授权的近似。实数恒等式、浮点等价和测试通过是不同结论；不能为了让候选通过而修改比较器或容差。
- 明确主目标及约束：调用延迟、稳态吞吐、尾延迟、内存或能耗；有多个目标时写清优先级。服务吞吐需绑定并发、请求分布和延迟约束，不能由单 kernel 加速比代替。
- 固定计量边界：是否包含分派、分配、转换、准备、通信、同步、恢复、输出处理，以及编译、首次调用和缓存建立。一次性成本与重复调用成本分别记录，摊销次数必须有依据。
- 基线采用目标环境中实际可用的合理实现，保留其优化配置。benchmark 分数可作指定验收项，业务收益仍以约定的运行指标解释；不把评分锚点当成物理极限。
- 缺少业务分布或精度约定时，先从调用者和已有材料补齐；仍未知就明确标注，并继续不依赖该信息的工作，不自行假定测试列表就是生产分布。

## 2. 先统计，再按成本家族分派

- 建立一份可增量更新的 workload 表：输入来源、shape、dtype、布局/stride、模式和可选输出、独立任务数、轴长、对齐和尾块。按算子补充必要特征，如 TopK 的 K/N、GEMM 的 M/N/K、卷积的 groups、扫描的依赖长度。
- 记录实际调用频次、每类完整路径耗时、资源占用和分布范围；需要数据快路时，再统计值域、重复率、稀疏度、异常和候选占用。频次未知时分别报告家族表现，不编造权重。
- 按主导成本分型：固定开销、并行不足、计算吞吐、带宽、跨轴访问、尾部浪费、同步依赖或恢复成本。一个家族的成本主因可以随硬件、并发和规模变化。
- 原始 shape 不同但合法展平后的语义和成本相同，可以属于同一家族；相同 shape 的不同 dtype、布局或模式也可能需要不同调度。每核工作量要结合实际工作划分估计，再由测量修正。
- 每个家族写清：合法资格、性能适用域、公共阶段、专用调度、分派优先级、workspace 及完整回退。边界来自成本变化和实测，不来自 case 编号。
- 一个家族可以有多个 launch；一个 kernel 也可以服务多个家族。融合、拆分、流水与重计算均可探索，不预设 kernel 数量或“一 shape 一 kernel”。
- 元数据足够时，先选择执行计划，再分配该计划的 workspace、执行转换和准备。依赖输入内容的选择在合适的执行侧完成，必要的发现、检查和同步都计入成本。
- 动态调优和计划缓存应绑定影响计划的硬件、软件、shape、dtype、布局与模式，定义失效条件，并单列调优/首次命中的代价。缓存计划与缓存输入相关结果要区分。

## 3. 先寻找能消去的工作，再选择实现工具

每个候选先简短回答：

1. 最终输出真正需要哪些信息？可以省掉什么计算、搬运、中间张量或等待？
2. 依据是什么：语义保证、数学性质、运行时充分条件，还是有界近似？
3. 新增哪些检查、准备、同步与恢复？失败集中在哪个最慢执行单元？
4. 哪块缓冲能提前释放，哪条依赖被删除，又新增了什么依赖？
5. 什么输入或硬件观察会推翻假设？哪一个最小实验能区分这些解释？

- 数据按用途选表示：数值、次序、索引、关系、统计量和状态可以采用不同形式。地址和索引的错误不能由数值输出容差掩盖。
- 优先检查重复准备、重复读取、完整物化、广播展开、过大中间表示和不必要的串行依赖；也允许增加缓冲、拆阶段或重计算来缩短关键路径。
- 数据分布只说明快路容易命中，不能代替正确性条件。猜测阈值、范围或稀疏结构后，必须取得足够证据；不成立时覆盖完整语义。
- 检查粒度与恢复范围一起设计：元素、行、tile、分区或整个调用。记录命中与恢复成本，兼顾最慢单元和尾延迟，不只看平均命中率。
- 对每块异步共享缓冲明确：写入者、读取者、最后读者、发布与可见性、下一次覆盖。指针相同不说明内容未变；跨调用复用结果需要有效的不可变性或版本依据。
- 差距主要来自结构时，允许重开布局、分解、表示、并行划分和计算位置。结构搭建可以有暂时较慢的中间版本，按完整方案验收；不要求先停滞固定轮数。
- 社区实现和历史成功经验提供候选机制。追溯其语义、硬件、编译器和调用条件；参数与平台指令不能脱离适用域照搬。

## 4. 代码围绕公共阶段与独立调度组织

| 差异 | 优先表达方式 |
|---|---|
| 相同语义与布局约定下的公式、编码、归并、地址计算 | 共享 helper，注明输入输出、精度和副作用 |
| 编译期已知且有代码生成收益的类型、宽度、模式 | 模板、静态分支或编译期参数 |
| tile、batch、线程/核数、预取深度 | 配置或有限的编译期实例 |
| 搬运布局、并行方式、缓冲生命周期、同步协议、恢复范围 | 独立调度，必要时独立 kernel 或编译单元 |

- 复用需要相同的语义、表示与生命周期合同，不因函数名字相似而强行合并。回退算法可以共享，其接管位置和恢复范围必须明确。
- 避免为了改变一个阶段复制整条搬入、计算、写回流水。新增独立调度说明已有结构难以经济表达的差异，以及新增的正确性和同步义务。
- 抽象若引入动态分支、地址开销、额外同步或更长的寄存器/缓冲存活期，再检查编译结果；保留专用实现也需要可复现的性能或覆盖价值。
- 不设通用代码行数上限。检查不可达分支、重复职责、无独立价值的变体和无用编译实例；保留解释精度、同步、布局及非显然常数的注释。
- 宏用于机械展开，不隐藏分派顺序、同步副作用和资源归属。共享阶段改变后，验收范围扩大到其全部消费者。
- 区分 helper 数、源码 kernel 定义数、编译实例数和单次实际 launch 数；源码短或文件少本身不证明更快、更简单。

## 5. 根据问题选择诊断工具

- 先确认正在测什么：源码/构建产物身份、编译配置、设备与软件版本、实际入口、调度参数和输入来源。源码中存在的优化不代表真实路径命中。
- 主机或系统时间线用于发现分派、准备、传输、通信、launch 间隙及重叠；设备 trace 和计数器用于定位忙闲、流量、资源压力、同步和负载不均。
- AST/预处理用于确认模板、宏、分派与可达性；IR/ISA 用于检查转换、地址计算、向量化、寄存器压力和实际同步。只有问题需要时才使用，不要求每轮跑全套。
- 明确工具版本、字段单位、计数口径、采样执行单元和 profiler 扰动。各管道时间、重叠等待或各核耗时不能相加当作调用关键路径。
- 模拟器和微探针用来区分机制，不替代目标设备完整路径测量。需要时用受控消融或临时跳过目标工作的诊断版本估计可回收成本；结果不能冒充正确实现的性能。
- 每次诊断必须指向可改变的布局、工作划分、资源占用或依赖。若观察不支持原假设，更新假设，不仅重复采集同类图表。

## 6. 用足够而不过量的验证决定去留

- 复用仍有效的历史证据，只补能改变当前决策的缺失检查。验证强度与语义、并发和影响范围匹配，不为局部改动无条件重跑所有工具。
- 正确性覆盖实际需求与新增假设的边界：家族交界、尾块、合法异常输入、并列、精度边界，以及快路接受/拒绝和恢复。按改动补独立输入池或定向反例，避免只复测用于调参的输入。
- 异步、状态或缓存改动额外验证相关生命周期，例如同地址不同内容、连续调用、多流及输出可见性。缺陷诊断与正常性能计时分开。
- 比较时固定输入池和计量协议，控制设备负载、频率、预热、缓存/地址复用、并发、编译与图捕获状态。按目标分别测首次调用、稳态或冷缓存，不把“总是清缓存”当成通用真实场景。
- 优先新旧交错配对测量，报告波动与逐家族结果；根据噪声增加独立轮次，怀疑位置偏差时再做同实现对照。单次最高值、历史最低耗时拼表和理论模型不作为实现成绩。
- 结构探索先检验关键假设；晋升时执行约定的完整验收，覆盖变更家族、共享消费者及未命中分派，并检查混合调用时的缓存和资源影响。
- 汇总按事先约定的调用分布和目标计算。串行成本可按调用次数加权；并发服务的吞吐和尾延迟需直接测量。总均值不能掩盖违反约定的家族退步或资源超限。
- 完整正确且可复现的正收益可以保留，不因预测收益小或代码改动不够“结构性”而拒绝。未解决的噪声、功能缺口和退步应明确报告，不改验收规则来宣布成功。

## 7. 整合、留档与交付

- 整合先确认分派与资源计划，再组合公共阶段和专用调度；保留覆盖未命中输入的实现。修改共享阶段时不以永久冻结旧机器码替代重新验收。
- 当前实现保留已验证的公共阶段、独立调度与必要回退。失败实验归档，记录改变了哪条认识，以及什么新条件出现后才值得重试。
- 结论绑定源码/构建配置、产物和测量报告。区分机制推测、探针结果、完整算子结果、调用链收益与部署结果。
- 发布保留许可证、必要构建信息和维护注释，交付与验收相同的产物；重新构建则重新绑定产物身份并完成受影响的验证。外部提交、发布与部署遵循用户授权。
- 只记录经过验证的机制及其适用域；尚未验证的方向明确标注。经验中保留反例、失败成本和来源，不只留下最佳参数。

## 任务附录：在具体项目中补齐

通用规则不固定芯片、框架、题集版本、评分公式、阈值、工具命令或提交流程。具体任务维护以下信息；可引用现有文件，不要求另建一套重复账本：

- 合同：接口/调用者、合法域、全部输出、精度与状态约束。
- 目标：主指标、计量边界、调用分布、资源与退步约束。
- 环境：设备拓扑、编译器/运行时、依赖、构建和执行入口。
- 基线：实现与产物身份、完整正确性及原始性能记录。
- 家族：特征、资格、适用域、公共阶段、分派、资源和回退。
- 实验：要省的工作、成立依据、反例、成本、最小改动与观察。
- 验收：代表输入、边界输入、完整测试及性能比较命令。
- 结论：实测收益与波动、未解决问题、保留/回退及证据路径。

最小工作顺序：读合同与现有证据 → 更新 workload 与成本家族 → 提出可推翻的假设 → 用必要的诊断选择路线 → 实现 → 配对比较 → 完整整合验收 → 更新经验。
